# Чекпоинт: GlobalID в конфигурации устройства

**Проект:** DAN Platform 2.0
**Дата:** 2026-07-30
**Статус:** реализовано и подтверждено на ATmega328P

## Зафиксированное решение

Идентичность конкретной прошивки вынесена из ядра в конфигурацию
устройства:

```text
src/config/device_config.hpp
├── Version
└── GlobalId
```

`GlobalId` расположен непосредственно после `Version`, как было
утверждено. Оба значения являются compile-time константами и не требуют
отдельных объектов в RAM.

Допустимый диапазон `GlobalId` остаётся протокольным: `1..30`.
Корректность значения проверяется через `static_assert`.

## Граница ответственности

- `main.cpp` является точкой сборки конкретного устройства и передаёт
  `dan::config::GlobalId` в `System`;
- `System` передаёт идентификатор в `Runtime`;
- `Runtime` передаёт его в `MessageDispatcher`;
- ядро больше не содержит идентификатор конкретного устройства;
- внутренние тестовые компоненты получают локальный идентификатор
  через уже инициализированный `MessageDispatcher`;
- настройки прикладных модулей остаются внутри самих модулей;
- `Logic` остаётся отдельным прикладным модулем;
- центральная `ConfigurationTable` для настроек модулей не создаётся.

## Реализация

Создан `src/config/device_config.hpp`:

```cpp
inline constexpr uint8_t Version = 1;
inline constexpr core::GlobalId GlobalId =
    core::MessageProtocol::FirstDevice;
```

Из `src/core/config/runtime_config.hpp` удалён `LocalDeviceId`.

Контракты инициализации теперь принимают идентификатор явно:

```cpp
System::Initialize(GlobalId globalId);
Runtime::Initialize(GlobalId globalId);
```

Диагностический routing-тест выбирает удалённый ID относительно
фактического локального ID диспетчера. `TestModule` также использует
фактический локальный ID при создании сообщения.

## Граница кирпичика

Этот чекпоинт не добавляет:

- настройки прикладных модулей;
- центральную таблицу конфигурации;
- EEPROM-хранилище;
- изменение `GlobalId` во время выполнения;
- загрузку `GlobalId` из внешнего хранилища;
- сетевой транспорт;
- новые runtime-модули.

Зарезервированный `ModuleID Configuration = 0x06` сохраняется, но
активный системный модуль `Configuration` не создаётся.
