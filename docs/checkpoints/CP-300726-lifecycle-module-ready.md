# Чекпоинт: правдивый жизненный цикл и готовность модулей

**Проект:** DAN Platform 2.0
**Дата:** 2026-07-30
**Статус:** реализовано; запуск ядра подтверждён на ATmega328P

## Зафиксированное решение

Контракт жизненного цикла передаёт фактический результат каждого
этапа:

```text
main
└── System::Initialize/Start
    └── Runtime::Initialize/Start
        ├── MessageDispatcher::Initialize/Start
        └── ModuleTable::InitializeModules/Start
```

`Module::Initialize()`, `Module::Start()`, `Runtime::Initialize()`,
`Runtime::Start()`, `System::Initialize()` и `System::Start()` возвращают
`bool`.

Состояние `initialized` или `running` устанавливается только после
успешного завершения соответствующего этапа. Повторный вызов уже
успешно завершённого этапа идемпотентен и возвращает `true`.

`main.cpp` выводит `[BOOT] System started` только при успешных
`System::Initialize()` и `System::Start()`. При отказе выводится
`[BOOT] System failed`.

## Готовность модулей

Таблица проходит по всем зарегистрированным модулям. Отказ одного
модуля не останавливает запуск остальных.

После успешных `Initialize()` и `Start()` модуль сообщает:

```text
Module 0x10 (ReadyModule) ready
```

ID печатается двумя шестнадцатеричными цифрами. Имя берётся из
`GetName()`; если имя отсутствует или пустое, скобки с именем
пропускаются.

Для отсутствующего, неинициализированного или не запустившегося модуля
строка `ready` не выводится.

На этом этапе «ответ модуля» означает синхронный `bool`-результат его
жизненного цикла. Отдельный служебный ping через DAN-сообщение, тайм-аут
и протокольный ответ не вводятся.

## Граница кирпичика

Этот чекпоинт не добавляет:

- модуль EEPROM;
- регистрацию модулей в стандартной сборке;
- центральную таблицу конфигурации;
- служебный DAN-протокол проверки готовности;
- тайм-аут ответа модуля;
- сетевой транспорт;
- настройки прикладных модулей.

EEPROM сохраняет зарезервированный системный `ModuleID 0x03` и будет
добавлен в стандартную сборку следующим отдельным кирпичиком.

## Проверка

Пройдены:

- host-тест успешного и повторного жизненного цикла;
- host-тест отказа `Initialize()` и `Start()` отдельных модулей;
- host-тест недопустимого `GlobalID`;
- проверка единственной строки
  `Module 0x10 (ReadyModule) ready` для трёх тестовых модулей;
- строгая host-компиляция с `-Wall -Wextra -Werror`;
- `git diff --check`;
- PlatformIO-сборка среды `nanoatmega328`;
- загрузка прошивки и запуск пустого состава на реальном ATmega328P.

Пользователь подтвердил 2026-07-30 следующий аппаратный вывод:

```text
[DIAG] Routing stage start
[BUS] Initialized
[DISPATCH] Initialized
[DISPATCH] Started
[BOOT] System started
```

Строка `Module ... ready` на целевой плате пока не проверялась, потому
что стандартная сборка ещё не регистрирует ни одного модуля. Её первая
аппаратная проверка запланирована вместе с EEPROM.
