# Checkpoint CP-270726-02

**Проект:** DAN Platform 2.0
**Статус:** Message Subsystem Integration Completed

---

## Архитектура платформы

```text
System
 ├── Platform
 └── Runtime
      ├── ModuleTable
      └── MessageBus
```

Жизненный цикл:

```text
Initialize()
Start()
Run()
Stop()
```

---

## Подсистема модулей

Утверждено:

```text
Runtime
    ↓
ModuleTable
    ↓
Module
```

Каждый модуль имеет жизненный цикл:

```text
Initialize
Start
Run
Stop
Receive
```

Получение сообщений осуществляется через единую точку входа:

```cpp
Module::Receive(...)
        ↓
Module::OnReceive(...)
```

---

## Подсистема сообщений

Формат сообщения окончательно принят.

Размер сообщения:

```text
8 bytes
```

Структура:

```text
Header      32 bit
ObjectId    16 bit
Value       16 bit
```

Header содержит:

```text
Sender
Receiver
MessageType
MessageAttribute
MessageId
```

---

## MessageQueue

Интегрирована рабочая реализация первой DAN Platform.

Особенности:

* кольцевой буфер;
* отсутствие динамической памяти;
* FIFO;
* фиксированный размер;
* соответствует DPAS.

---

## MessageBus

Интегрирован.

Поддерживает:

```text
Publish()

Pop()

HasMessages()

Clear()

Count()
```

Bus не интерпретирует сообщения.

Bus является исключительно транспортом.

---

## Dispatcher

Архитектура упрощена по сравнению с первой DAN Platform.

Удалены:

```text
ObjectRegistry

ObjectDispatcher

ObjectValidator
```

Текущая схема:

```text
MessageBus
      ↓
MessageDispatcher
      ↓
ModuleTable
      ↓
Module
```

---

## Runtime

Основной цикл имеет вид:

```text
Runtime
    ↓
MessageDispatcher::ProcessAll()
    ↓
ModuleTable::Run()
```

Очередь сообщений полностью обслуживается до выполнения очередного цикла модулей.

---

## Broadcast

Добавлена поддержка широковещательной доставки.

Схема:

```text
MessageDispatcher
        ↓
ModuleTable::ReceiveBroadcast()
        ↓
каждый зарегистрированный модуль
```

---

## Принятые архитектурные решения

Утверждено:

* отсутствует Object runtime;
* отсутствует ObjectTable;
* отсутствуют Object Handler;
* отсутствует объектная диспетчеризация.

Интерпретация сообщения полностью принадлежит модулю.

```text
Message
      ↓
Module
      ↓
switch(ObjectId)
      ↓
switch(MessageId)
```

---

## Протокол DAN

Утвержден принцип:

Каждый тип функционального модуля реализует единый стандарт DAN Protocol.

Например:

```text
DAN PWM Standard

DAN Button Standard

DAN Temperature Standard
```

Отличается только ModuleId.

Команды остаются одинаковыми.

---

## Единый словарь протокола

Описание команд хранится централизованно.

И Logic, и Module используют один и тот же набор определений.

Модуль не придумывает собственный протокол.
