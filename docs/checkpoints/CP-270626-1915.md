# CHECKPOINT — DAN Platform Core + Network Architecture v1.0

## 1. Архитектура ядра

Полностью завершены и проверены:

```text
Platform
Runtime
Diagnostics
Module
ModuleTable
Message
MessageBus
MessageDispatcher
```

Все компоненты успешно протестированы на реальном оборудовании.

---

## 2. Архитектура сообщения

Формат сообщения остаётся неизменным.

```cpp
struct Message
{
    uint32_t header;
    ObjectId objectId;
    MessageValue value;
};
```

Размер сообщения:

```text
8 bytes
```

Изменять его **не планируется**.

---

## 3. Семантика Header

Header окончательно определён:

```text
Sender
Receiver
Type
Attributes
MessageId
```

где

```text
Sender      → модуль-источник

Receiver    → модуль-получатель

MessageId   → операция

ObjectId    → объект

Value       → параметр
```

---

## 4. ObjectId

Принято решение:

`ObjectId` описывает **объект**, а не сервис.

Примеры:

```text
StatusLed
Motor1
Temperature
Battery
Button1
```

---

## 5. Runtime не знает о сети

Runtime остаётся полностью локальным.

Он не содержит:

* CAN
* BLE
* RS-485
* Ethernet
* Wi-Fi

Это обычные модули платформы.

---

## 6. Транспорт

Любой транспорт является обычным модулем DAN.

Например:

```text
CAN Module

BLE Module

RS-485 Module

Ethernet Module
```

Все они работают одинаково:

```text
Internal Message
        ↓
Transport
        ↓
Network

Network
        ↓
Transport
        ↓
Internal Message
```

---

## 7. Главная архитектурная идея

Вся сеть выглядит как **единая логическая система**.

Для Logic нет разницы:

```text
PWM находится внутри устройства

или

PWM находится на другом контроллере.
```

API взаимодействия одинаковый.

---

## 8. ModuleId

Принято ключевое решение.

**ModuleId является глобально уникальным идентификатором во всей системе DAN.**

Следствия:

* отдельный `NodeId` не требуется;
* структура сообщения не изменяется;
* внутренний и внешний обмен используют один и тот же формат сообщения;
* транспортные модули обеспечивают доставку между устройствами.

---

## 9. Конфигурация

Каждое устройство формируется через `ConfigurationTable`.

Через неё:

* включаются необходимые модули;
* назначаются их `ModuleId`;
* формируется конкретная конфигурация устройства.

Исходный код модулей остаётся неизменным.

---

## 10. Пространство ModuleId

Принято решение зарезервировать диапазоны идентификаторов.

Предварительная схема:

```text
0x00        Invalid

0x01–0x1F   Системные модули

0x20–0x7F   Стандартные модули DAN

0x80–0xEF   Пользовательские модули

0xF0–0xFE   Reserved

0xFF        Broadcast
```

Это обеспечивает единый стандарт развития платформы.
