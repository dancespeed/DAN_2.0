# Чекпоинт: неприкосновенный реестр системных ModuleID

**Проект:** DAN Platform 2.0
**Дата:** 2026-07-29
**Статус:** реализовано и проверено host-тестами

## Зафиксированный реестр

`ModuleID` остаётся 6-битным протокольным адресом,
физически представленным типом `uint8_t`.

```text
0x00       Invalid
0x01       System
0x02       Message
0x03       EEPROM
0x04       Network
0x05       Runtime
0x06       Configuration
0x07-0x0F CoreReserved
0x10-0x3E Application
0x3F       Broadcast
```

Системный диапазон `0x01-0x0F` является частью стандарта DAN:

- системные ID одинаковы во всех устройствах;
- занятый или зарезервированный системный ID не может быть назначен
  прикладному модулю;
- отсутствие системного компонента в конкретной сборке не освобождает
  его ID;
- добавление ID в реестр не превращает внутренний класс ядра
  в адресуемый `Module`;
- `Logic` и остальные модули конкретного устройства используют
  диапазон `0x10-0x3E`.

`0x00` и `0x3F` остаются специальными значениями протокола
`MessageProtocol`, а не адресами модулей.

## Реализация

В `core/module/module_ids.hpp` определены:

- неизменяемые ID `System`, `Message`, `Eeprom`, `Network`, `Runtime`
  и `Configuration`;
- границы `FirstCore`, `LastCore`, `FirstApplication`
  и `LastApplication`;
- compile-time проверки `IsCore()` и `IsApplication()`;
- `static_assert` для утверждённых значений и непрерывной границы
  системного и прикладного диапазонов.

Старый диагностический `TestModule` больше не занимает `0x01`.
Его ID расположен в самом тестовом модуле и равен
`FirstApplication` (`0x10`).

## Граница кирпичика

Этот чекпоинт не добавляет:

- адресуемые реализации `System`, `Message`, `EEPROM`, `Network`,
  `Runtime` или `Configuration`;
- EEPROM-хранилище;
- проигрывание `ConfigurationTable`;
- назначение ID во время загрузки;
- решение о хранении `GlobalID`.

## Проверка

Пройдены:

- compile-time проверки реестра;
- `message_core_test` с тестовыми модулями из прикладного диапазона;
- host smoke-тест пустого жизненного цикла `Runtime`;
- компиляция host-тестов с `-Wall -Wextra -Werror`;
- `git diff --check`.

AVR-сборка в этом окружении не выполнялась: PlatformIO и `avr-g++`
недоступны.
